How to use this guide
Follow the procedure, then its screen plates
Each numbered procedure states the starting point, actions, expected result and a watch point. Screen
plates immediately afterward show the real interface. Enlarged details preserve small labels. PDF
bookmarks provide direct navigation.
Know which environment is shown
The first library image is a read-only production capture. Authoring screens use the locally running
dashboard with a non-clinical TRAINING ONLY document, version SOP-2026.1. The public reader and
published-state plates use a separate existing local fixture.
What this walkthrough actually reached
The two-page training source was uploaded, corrected, saved through revision 3, regenerated,
individually and bulk reviewed, and accepted. Completeness reported 9/9 reviewed blocks and all
publication gates passing. The final Publish confirmation was inspected and canceled. No production
clinical records were changed.
Understand the mobile evidence
Dashboard mobile previews are labeled as previews. Android app plates come from the repository’s
real store screenshot assets and show a different guideline. On-device publication, synchronization
and offline checks remain required for each real edition.
Use the expected result as a gate
Stop and investigate a mismatch between source, actual rendered content, report or target edition.
Screen counts and layout vary with document size, permissions and software version. Training counts
are examples, never a substitute for full review.

01 The complete workflow
Use this map to keep the source, generated content, review decisions and public version
aligned.
1. Create and upload
Create a guideline document and a version. Upload the authoritative source and wait for processing.
See the corresponding procedure and screen plates.
2. Edit and regenerate
Correct the Markdown, tables and images. Save the intended revision and regenerate its reader
content. See the corresponding procedure and screen plates.
3. Review and accept
Review ordinary prose as well as safety-sensitive blocks. Check completeness and accept the exact
regenerated revision. See the corresponding procedure and screen plates.
4. Publish and verify
Validate and publish, then verify the website, mobile reader, downloads and search. See the
corresponding procedure and screen plates. Notifications, updates and exceptions follow in
procedures 24-28.
Continue when
Saving, reviewer assignment, generation completion and a private preview do not publish a guideline.
Watch point: Keep the last approved publication available while its replacement is prepared.

02 People, access and preparation
Assign responsibility before starting. The organization must authorize clinical decisions and
publication.
1. Author / editor
Needs document creation access plus guideline.markdown.read, guideline.markdown.edit,
guideline.markdown.upload, guideline.asset.manage and guideline.structure.regenerate for the
assigned work. Prepare the authoritative PDF or UTF-8 Markdown, images and issuing organization.
2. Reviewer
Uses guideline.review. High-risk clinical decisions and regeneration acceptance also require
guideline.high_risk.approve. Compare content with the authoritative source; use an independent
reviewer where local governance requires it.
3. Publisher
Needs guideline.publish and access to the document. The server still enforces publication validation.
An administrator cannot bypass missing review by changing a dashboard badge.
4. Before uploading
Confirm title, document kind, version label, source organization, country, language, publication/review
dates, applicable categories and diseases. Avoid patient-identifiable information in training files or
review notes.
Continue when
An active account with the correct role can see the expected controls. If a control is missing, ask an administrator to
check permissions.
Watch point: Assignment is coordination, not clinical approval. Never approve content merely to clear a warning.

03 Choose the correct document route
The selected document kind determines whether readers receive structured content, an
original file, or a link.
1. Structured clinical guideline
Choose a normal guideline kind for searchable, editable chapters and blocks. Upload PDF, .md or
.markdown. Follow the full editing, regeneration, review and publication process in the following
procedures.
2. Publish as uploaded
Some kinds, such as forms, keep the PDF or Word (.docx) file exactly as uploaded. Text indexing
supports discovery, but there is no Markdown editing or structured-block workflow. See the
special-routes procedure.
3. Publish as link
A link kind publishes a complete HTTPS URL. No source file is uploaded and no extraction or
Markdown editor runs. Review the destination before publishing. See the special-routes procedure.
4. Choose deliberately
Use categories and diseases for discovery. Legacy program area is optional. If the expected structured
workflow is absent, check the document kind instead of uploading the same file repeatedly.
Continue when
For an editable clinical guideline, continue with the structured route.
Watch point: Do not select an original-file or link kind just to avoid clinical review requirements.
Screen plates follow: The four-stage creation wizard

04 Create the guideline record
Dashboard > Clinical Guidelines > Create Guideline. This record describes the document
across all its versions.
1. Open the creation wizard
Select Create Guideline from the guidelines area. The four stages are Create guideline, Create
version, Upload version, and Review and edit.
2. Complete the metadata
Enter the official title and select Document kind. Add Source organization, Country and Language
code. Add a description that explains the document without changing its clinical meaning.
3. Classify for discovery
Select every relevant Category and Disease, then a Primary disease from the selected diseases. Use
active taxonomy entries. Classification supports browsing and hub placement; it is not publication
approval.
4. Save the record
Select Create and Continue. Confirm that the next stage names the correct document. To correct
document-level metadata later, use Edit Metadata on the document page.
Continue when
The guideline record exists and the wizard advances to Create version.
Watch point: Use the source title consistently; a template title or unrelated Markdown H1 can block publication.
Screen plates follow: Completed document metadata
Field-by-field check
Title: exact official source title. Document kind: choose the intended structured/original/link route. Legacy program area:
optional where shown. Source organization: issuing body, not an author signature. Country and language: match the
document. Categories/diseases: select relevant taxonomy entries; Primary disease comes from selected diseases.
Description: a short accurate summary.
After Create and Continue
The record is saved and Create version becomes active. If validation fails, stay on this form and correct the named field; do
not create a second record to retry.

05 Create the first version
Document version labels identify the clinical edition; they are separate from the MediGuide
application release.
1. Name the edition
In Create first version, enter the official Version label, such as 2026.1. Choose a label that is unique for

to the document, where New Version can create additional editions.

are immutable; updates use a new draft rather than an in-place edit.

Watch point: Do not reuse an existing edition label for a replacement. Retain older versions for audit.

06 Upload the authoritative source
The source is the fidelity reference for every subsequent correction and clinical review
decision.
1. Choose a supported file
In Upload guideline source, choose the authoritative PDF or UTF-8 Markdown (.md / .markdown). The
creation screen allows up to 100 MB. For an existing draft, use Upload PDF to open the source dialog,
which also accepts Markdown.
2. Transfer the source
Select Upload source. The screen checks the file, transfers it, verifies storage and queues processing.
Keep the selected version unchanged during the upload.
3. Resume safely
Pause is available during transfer. To resume, choose the same file and select Resume upload; the
screen preserves completed upload parts for up to 24 hours. Cancel upload abandons the transfer
session.
4. Choose another starting path if needed
Start with blank Markdown or Start from template opens authoring without PDF extraction. Existing
Markdown may also be loaded from the editor. Obtain the original images separately for Markdown
imports.
Continue when
Storage verification finishes and Source transfer and processing shows a real processing job.
Watch point: An upload reaching 100% is not proof that extraction, indexing, clinical review or publication succeeded.
Screen plates follow: Choose the source route; Source selected, before transfer
Before Upload source
Confirm the selected filename appears in the upload panel. Removing or replacing a selected file before transfer is different
from replacing an already published edition. Keep the authoritative source in the approved document archive.

07 Monitor extraction and indexing
Wait for the real processing result. A large PDF can take time, especially when OCR or table
extraction is required.
1. Watch the stage list
Follow Source transfer and processing. It reports the current stage, progress, attempts and any
available timings. The wizard refreshes while extracted Markdown is still unavailable.
2. Wait for usable output
When processing completes, open the document and choose Edit Markdown or Editorial Review as
appropriate. Preview original keeps the source available for comparison; processing completion alone
does not make extracted blocks approved.
3. Handle a failed job
Read the error and failing stage. Retry processing is offered for eligible failed/canceled jobs and
reuses completed checkpoints where possible. An automatic retry time may also be shown.
4. Escalate a persistent failure
Record the title, version, job identifier, stage, attempt count, time and error. Ask an administrator to
investigate worker/storage/embedding failures. Do not create several duplicate documents to work
around one job.
Continue when
The correct draft has its extracted source and is ready for editorial work.
Watch point: Do not assume a fixed completion time or that a quiet progress bar means the job has failed.

08 Open the Markdown workspace
Document > draft version > Edit Markdown (or Author Markdown when starting without
extracted source).
1. Check the version and revision
Confirm the guideline title and version. The editor shows the saved revision and structured-content
status. Work in the draft intended for publication.
2. Choose a working view
Use Edit, Split or Preview. Split makes it easier to compare source syntax and rendered output. Use
Original PDF where available to verify fidelity; Markdown-only sources cannot claim PDF page
citations.
3. Inspect the whole document
Review the outline, front matter, chapter boundaries, paragraphs, lists, links, tables, figures and
footnotes. Check the beginning, middle and end, not only the first chapter.
4. Use private previews carefully
Reader, mobile, search and RAG presentations help expose structural problems. They are previews,
not evidence that content has been published or clinically approved.
Continue when
The editor contains the correct complete source for the draft edition.
Watch point: Retain the authoritative source beside the editor. Extraction can lose text or reorder content without an obvious
syntax error.

09 Repair headings and reading order
A clear hierarchy becomes the chapter and section navigation on the website and mobile app.
1. Use one document title
Keep one H1 (# Guideline title). Use H2 (##) for chapters or major front matter, H3 for major sections
within a chapter and H4 for subsections. Do not skip heading levels.
2. Match the source structure
Preserve the sequence and meaning of chapters. Remove repeated page headers/footers only after
checking the source. Keep clinically meaningful notes, references and appendices.
3. Replace training/template content
Replace template titles, unchanged template headings and every _Add reviewed clinical content._
marker. A template provides structure, not clinical wording.
4. Check navigation and anchors
Preview the section outline and internal links. Renamed headings may retain stable anchors from
revision metadata; verify that links still lead to the correct clinical section.
Continue when
One coherent title and an unbroken parent-child outline match the source.
Watch point: A normal single H1 acts as the document wrapper; its H2 children become mobile chapter cards. Do not create
extra H1 headings just to obtain more cards.
Screen plates follow: Corrected heading hierarchy
Worked correction in the screenshots
Extraction produced “# Introduction” and repeated section labels. The demonstration replaces them with one exact document
H1 and two source-matching H2 chapters. The table and the full prose are preserved. Real clinical corrections require source
evidence.

10 Upload and reconnect images
Use Assets in the editor to manage version-scoped images and their attribution.
1. Gather the exact figures
Obtain the source images or extract them from the authoritative PDF. Check charts, axes, legends and
labels. Do not substitute a similar chart when the required original is missing.
2. Complete asset metadata
Open Assets > Guideline asset library. Choose, drop or paste images. Supported files are PNG, JPEG,
GIF and WebP, up to 10 MB each. Provide meaningful alternative text; add caption, source, attribution
and license as applicable.
3. Insert the correct reference
Upload the image, inspect its preview and insert it where it belongs. Prefer the stable guideline-asset://
reference returned by the library. Resolve Broken references and ambiguous filenames before
regeneration.
4. Review clinical figures
Mark clinically sensitive figures appropriately. Review the asset and generated figure against the
source. A figure is not ready for publication simply because its image loads.
Continue when
Every intended image resolves to the correct version asset with meaningful alternative text.
Watch point: Replacing a clinical figure requires a fresh source check. Missing or unreviewed referenced assets can block
publication.
Screen plates follow: Version asset library; Image metadata before upload; Uploaded image ready to insert
Placement and reference check
Put the insertion cursor at the intended location before Insert. Confirm the Markdown contains the intended guideline-asset://
reference and that the rendered preview loads the same figure. Remove accidental duplicate references only after checking
context.

11 Repair and verify clinical tables
Table formatting and clinical correctness are separate checks. Both must pass.
1. Preserve the cell grid
Each Markdown table needs a header row, a separator row and an equal number of cells in every row.
Keep empty leading or trailing cells and escape literal pipes inside cell text when needed.
2. Use the visual table editor
Inspect the whole grid before adding, deleting or moving rows/columns. Preserve the source headings,
merged-cell meaning, notes and reading order. Verify rendered output after each structural edit.
3. Check every clinical detail
Compare headers, row associations, values, decimal points, units, age/weight groups, routes,
intervals, footnotes, caption and source page. Never infer a missing dose or unit to make a table look
complete.
4. Save and regenerate
A valid table may still show high_risk_table_review_required. Save the source, regenerate, then
approve the generated table individually in Editorial Review after source comparison.
Continue when
The rendered grid is faithful to the authoritative table, including intentionally blank cells.
Watch point: Do not remove a row or warning merely to reach zero warnings. A syntactically valid table can still be clinically
wrong.
Screen plates follow: Visual Markdown table editor
Table dialog controls
Title describes the table; Caption preserves explanatory context; Source records provenance. Set each header and its
alignment, then add or remove rows/columns only as required by the source. CSV controls affect the grid; Footnotes retain
qualifying notes. Inspect Preview before Update Markdown table. Cancel abandons the proposed table edit.

12 Prepare, save and checkpoint
Save the exact source you intend to regenerate. Autosave and checkpoints are not publication
actions.
1. Inspect preparation proposals
Select Prepare for review. Review its before/after diff and Automatic, Editor review and Manual review
categories. Apply only changes that preserve source meaning; preparation does not approve clinical
content.
2. Resolve blocking errors
Use the validation panel and source-line guidance to fix malformed tables, unsafe/unsupported
markup, missing alternative text, broken links and invalid hierarchy. Warnings about tables and doses
usually remain review obligations.
3. Save the revision
Select Save draft and confirm the revision badge updates. Regenerate is disabled while changes are
unsaved. A saved revision is immutable; saving newer source makes the previous structured
projection outdated.
4. Create a named milestone
For a substantial change, use Checkpoint and describe the change. If a conflict occurs,
preserve/export your local work, load the current server revision and reconcile differences; do not
overwrite another author blindly.
Continue when
The intended source is saved on the server and has no regeneration-blocking errors.
Watch point: Local settings and local drafts are not a substitute for a confirmed server save. Do not regenerate from an older
revision.
Screen plates follow: Prepare for review is a proposal; Saved source with stable image reference; Immutable revision history;
Compare source revisions
Practical save sequence
After typing, wait for All changes saved or use Save draft when enabled. Read the revision number. Create a meaningful
Checkpoint before a large change when the control is available. Use History to compare the relevant revisions; restoration
creates a new source state that needs fresh regeneration and review.

25 Update, withdraw or restore access
Published clinical content is immutable. Corrections use a new edition; urgent removal uses
withdrawal.
1. Prepare a replacement edition
Open the published Markdown read-only view and choose the draft-from-published action. Enter a new
unique version label. The immutable source is copied; regeneration does not run automatically.
Correct, save, regenerate, review, accept, validate and publish.
2. Withdraw unsafe public content
An authorized publisher can select Withdraw and record a reason. This removes the document from
website, app discovery, search and AI retrieval while retaining files and history. Follow local incident
communication procedures.
3. Revise a withdrawn document
Choose Revise document or Continue draft. Use a new unique version label, check any
omitted-content warnings and complete the full workflow. The document stays withdrawn while you
work.
4. Republish unchanged approved content
Review and republish runs publication checks for the approved edition. Review the withdrawal
reason/history and attest readiness. If clinical wording must change, publish a new reviewed draft
instead.
Continue when
The public state matches the clinical decision, and the history explains the change.
Watch point: Downloaded copies are removed when devices next check online. Withdrawal cannot instantly reach a device
that remains disconnected.

26 Special routes: forms and links
Use these paths only for document kinds intentionally configured to publish an original file or
external URL.
1. Original-file route
Create document and version, then Upload file. Choose the correct PDF or Word (.docx), Upload
source and wait for text indexing. Review form shows the file exactly as readers will receive it; use
Preview original to check every relevant page.
2. Publish an original file
Confirm readability, edition, source, metadata and the indexing result. Publish from the document page
when checks pass. No Markdown, regeneration or structured-block editor is used for this route; a
corrected file belongs in a new draft version.
3. External-link route
Create document and version, choose Add link, enter the complete HTTPS URL and save. Review the
actual destination, title, organization, availability and mobile behavior. No file extraction or Markdown
workflow runs.
4. Verify the reader result
Publish after required checks, then test the public website and app opening behavior. For links, content
and access may change at the external host; for original files, verify the actual PDF/Word layout and
download behavior.
Continue when
Readers receive the intended reviewed original file or valid external destination.
Watch point: Do not promise offline availability or structured clinical page citations for an external link. Route-specific
publication checks still apply.

27 Troubleshoot without losing work
Fix the cause at the correct stage. Keep evidence and avoid duplicate uploads or unreviewed
shortcuts.
1. Upload or processing stalls
Distinguish transfer progress from the processing job. Resume with the same file when eligible. For
repeated failures, capture job/stage/attempt/error and ask operations to check storage, workers and
embedding services.
2. Regenerate is disabled or stale
Save unsaved changes and fix blocking Markdown errors. For a newer-revision warning, reload the
current revision and regenerate it. Preserve local edits before resolving a server conflict.
3. Review or publication is blocked
A high-risk table warning usually means individual review is still needed. Resolve missing image
references, invalid typed payloads, rejected blocks, missing reviewed prose, empty leaves and
unexplained coverage regressions. Refresh approval status before acceptance.
4. Published content is absent
Verify the current published edition and withdrawal state, then test a signed-out website view and a
refreshed online app. Check taxonomy/filter placement, synchronization, download age and
search/index readiness. Escalate with document/version IDs and exact failing reader steps.
Continue when
The issue has a reproducible cause, an owner and a safe next action.
Watch point: Never remove clinically meaningful content, invent missing evidence, bulk-approve high-risk blocks or republish
a template to make a validator pass.

28 Publication handover checklist
Use this checklist as the minimum operational record for an edition. Complete it before calling
publication finished.
1. Source and authorship
Record document title/ID, kind, version/ID, issuing organization, source filename and edition, source
revision/checkpoint, author, reviewer and publisher. Record the changes made and any unresolved
source questions.
2. Review and readiness
Record the regenerated revision/job, completeness report export, ordinary-content review, individual
high-risk/asset decisions, accepted regeneration and a passing publication validation. No unexplained
content-loss or empty-clinical-section issue remains.
3. Publication and reader checks
Record publication time, current edition, public URL, web test result, mobile build/device, online
discovery result, downloaded edition and offline check. Include representative table, figure and RAG
citation checks where applicable.
4. Aftercare
Name the owner for defects, review-due date and withdrawal/escalation contact. Record the optional
notification campaign separately. Keep audit exports in the organization's approved location; do not
attach credentials or patient data.
Continue when
Publication is complete when the correct reviewed edition is current and reader-facing verification is recorded.
Watch point: If verification fails, keep the issue open and assess withdrawal or a corrective edition under local governance.
